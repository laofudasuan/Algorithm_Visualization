# 分块算法

## 算法介绍

诸如区间加法，询问区间和这样的经典问题可以用分块解决。这些也可以用带$\log$的数据结构做。

但是如果操作变得更加复杂，很多时候$\log$数据结构无法进行维护就考虑使用分块了。

在区间修改/查询时，会穿过若干个整块和最多两个散块

比如查询$[2,7]$，穿过了$1 \sim 3$和$7 \sim 9$这两个散块和$4 \sim 6$一个整块：散块可以暴力，整块可以用整体信息

所以我们可以$O(1)$维护整块信息，$O( \sqrt{n} )$查询零散块信息

这样就达到了单词操作$O( \sqrt{n} )$的复杂度

## 理解方式

换一种理解方式

可以把序列分块，看成线段树的拓展

由原本的二叉树拓展到多叉树


##### P2801 教主的魔法

维护一个序列

- 区间加
-查询区间小于$x$的数个数

<CollapsibleComponent title="做法">
如果是单点修改，我们可以用树套树实现

但是区间修改后树套树无法快速合并信息

比如我们维护了cur的一个名次数据结构

cur的左儿子没有发生变化

cur的右儿子被整体加了

这样我们无法通过这两个儿子的名次数据结构快速维护出cur的名次数据结构

也无法直接在cur的名次数据结构上操作

所以分治结构无法在低复杂度解决这个问题
    
分块，维护每块的OV（就是排序后的数组）

每次区间加的时候

整块可以打一个标记

零散块可以重构

每次查询的时候

整块查询小于$x$的数，这个整块的标记为$y$（也就是说这一块所有数都加了$y$）

则等价于查整块的排序后的数组里面小于$x-y$的数的个数

这个可以二分

零散块就直接暴力查询块内在查询区间内的数是否满足条件
    
设有$x$个块

查询复杂度：

整块$O( \log(n / x) ) \times x$

零散块$O( n / x )$

修改复杂度：

整块$O( 1 )$

零散块$O( n / x )$ （重构的时候用归并）

按照根号平衡算一算可以发现

总复杂度$O( m\sqrt{ n\log n } )$

此时块大小为$\sqrt{n\log n}$

</CollapsibleComponent>

##### P5356 Ynoi2017 由乃打扑克

维护一个序列

- 区间加
- 查询区间k小

<CollapsibleComponent title="做法"> 

如果直接套用上一题的做法

每次查询的时候二分答案，然后查询区间中小于$mid$的数个数

复杂度是$O( m\sqrt{n\log n }\log n )$的

很遗憾，被卡掉了

将块大小设为$\sqrt(n)\log n$

每次修改显然复杂度为$\sqrt{n}\log n$

二分答案，每次查询

则有$\sqrt{n}/\log n$个整块，这部分复杂度为$O( \sqrt{n} )$单次

有$sqrt{n}\log n$个零散的点，这部分复杂度为$O( \sqrt{n}\log n )$单次

想办法优化掉零散点的复杂度

可以预先先把零散的两个块归并成为一个假的块

这样我们每次二分答案之后只用在这个假的块上面二分即可

总复杂度$O( m\sqrt{n}\log n )$

\begin{frame}[label=PRO]{CF1083F The Fair Nut and Amusing Xor}
“Fair Nut” 有两个长度为 $n$ 的数组 $a$ 和 $b$。他已经拥有这两个数组很久了，甚至没人知道它们是什么时候到他手里的。

“Fair Nut” 经常会修改数组中的数字。他还很关心每次修改后，数组 $a$ 和 $b$ 有多相似。

我们定义两个数组的相似度为：将两个数组变为相同所需的最小操作次数（每次操作可以对两个数组都进行）。如果无法做到，则相似度为 $-1$。

每次操作，你可以选择一个长度为 $k$ 的子数组（$k$ 是固定的），并将该子数组内的每个元素 $a_i$ 变为 $a_i \oplus x$（$x$ 可自选），其中 $\oplus$ 表示按位异或运算。

“Fair Nut” 已经计算出了每次修改后数组的相似度。你能做到吗？

注意，你只需要计算这些值，无需实际执行操作。

$1 \le k \le n \le 2 \times 10^5, 0 \le q \le 2 \times 10^5,0 \le a_i,b_i <2^{14}$
\end{frame}

\begin{frame}[label=PRO]{CF1083F The Fair Nut and Amusing Xor}
首先，区间修改的问题，可以通过前缀和变成两个单点修改。这样就变成了：每次可以选择两个距离为$k$的元素$\oplus x$

暴力算法可以贪心，从前往后只要遇到非零数$a_i$就操作一次$a_i$和$a_{i+k}$

根据贪心算法，可以将序列元素按照模$k$分组，这样，一个元素需要被操作当且仅当在这一组的前缀和非$0$

因此问题转化为了区间异或、求序列中$0$的数量

将序列分块，散块可以暴力修改；对于整块，可以打上标记，查询$0$的个数就是求有几个数等于标记
\end{frame}

\noindent 20pts \( n \leq 2000 \)

实现比较好的话应该也可以通过 \( n = 10000 \) 的部分。

时间复杂度 \( O(n^2) \)。

\noindent 另30pts 不强制在线

实际上有一大堆乱七八糟的做法，这里选几种。

由于不强制在线，因此所有用到的区间都是知道的，可以把它们全部记录下来，这样的区间一共有 \( O(n) \) 个。

接下来就是求 \( O(n) \) 个区间的逆序对个数，随你怎么求，比如分块，比如莫队。

时间复杂度在 \( O(n\sqrt{n}) \) 至 \( O(n\sqrt{n}\log n) \)。
\end{frame}

\begin{frame}[label=PRO]{洛谷NOIP2025模拟赛}
    
\noindent 100pts 无额外限制

首先在区间逆序对可以使用分块做到 \( O(\sqrt{n}) \)（P5046 [Noi2019] 模拟赛 Yuno loves sqrt technology I），因此直接用这个做法可以做到 \( O(n\sqrt{n}) \)。

但是实际上每次删点都是将区间一分为二，所以这些区间是有结构性的性质的，直接套最暴力的分块做法显然丢掉了这个性质。

先考虑如果是加点怎么做，在合并三个部分 L, p, R 的时候，新的逆序对数由这几部分组成：
\begin{itemize}
    \item 位置 p 产生的贡献，可以用主席树直接查询得到
    \item L, R 内部的贡献，由之前的信息直接得到
    \item L, R 之间的点对，考虑启发式合并，枚举较短的那一段，在另一段中查询，也可以用主席树进行维护
\end{itemize}
这样使用启发式合并的方法可以做到 \( O(n\log^2 n) \) 的时间复杂度。

现在是删点的情况，也就是一个整体到 L, p, R 的过程，也分三部分的贡献：
\begin{itemize}
    \item 位置 p 产生的贡献，可以用主席树直接查询得到
    \item L, R 之间的点对，考虑启发式分裂，枚举较短的那一段，在另一段中查询，也可以用主席树进行维护
    \item L, R 内部的点对，较短的那一段可以直接计算出来，较长的那一段不能直接计算，但是可以用整段的逆序对数减去之前求的这几部分计算得到
\end{itemize}
这样使用启发式分裂的做法就可以做到 \( O(n\log^2 n) \) 的时间复杂度。

这道题充分体现了需要根据询问的性质来设计算法，直接套用通用的分块做法会丢性质，复杂度更差的同时代码也不好写。

\end{frame}
