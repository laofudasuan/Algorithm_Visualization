橡皮筋形成的是**凸包的边界**；这条边界连同围住的区域，才是完整的凸包。

算法题里“求凸包”通常指：按顺时针或逆时针顺序，输出边界上的顶点。

但“把所有点圈起来”还不够，为什么一定要强调“凸”？

### 先理解“凸”，再理解“最小”

一个集合是**凸集**，当且仅当：任取集合中的两个点，它们之间的整条线段也都在集合中。直观地说，凸的区域没有向内凹进去的缺口。

对于点集 $S$，它的凸包 $\operatorname{conv}(S)$ 是**包含 $S$ 的最小凸集**。“最小”是按集合包含关系理解的：任何一个包含 $S$ 的凸集，都必须包含 $\operatorname{conv}(S)$。

所以一个候选区域必须同时满足三件事：

1. **包含全部点**：点可以在内部，也可以在边界上，不能漏在外面。
2. **区域是凸的**：任意两点之间的连线不能穿出区域。
3. **不能再缩小**：不是随便找一个足够大的凸多边形就算完成。

### 内部点、边界点和顶点不是一回事

在上方演示的初始点集中，真正的凸包是一个不规则六边形，顶点逆时针依次为 **J → A → E → F → G → I**。它的边不必平行于坐标轴，边长和内角也不必相等。

| 点的类型 | 图中的例子 | 是否需要作为凸包顶点输出？ |
| :-- | :-- | :-- |
| 凸包顶点，也叫极点 | J、A、E、F、G、I | 需要，它们是边界的拐角 |
| 边界上的共线中间点 | H 在 A、E 之间 | 取决于题目要求；只输出拐角时不保留 |
| 严格内部点 | 初始位置的 B、C、D | 不需要，它们没有撑住外层边界 |

注意：**凸包包含所有输入点，但凸包的顶点序列不一定包含所有输入点。**

输入不足以围成多边形时也有凸包：没有点时为空集；只有一个不同的点时是这个点；所有点共线时，是最远两个端点之间的线段。不能总把凸包定义成“面积最小的多边形”，否则这些退化情形会被漏掉。

后面的代码和演示统一采用以下约定：**先去重，只保留拐角，逆时针输出，不在末尾重复首点；全共线时只保留两个端点。**

## 构造方法（P2742 【模板】二维凸包）

### 共同工具：用叉积判断转向

沿着一个凸多边形的边界逆时针走，每到一个真正的顶点，都应该向左转。Graham 和 Andrew 两种算法，都是先确定一个扫描顺序，再不断修正不合法的转向。

设当前检查的三个点依次为 $A,B,C$，定义

$$
\operatorname{cross}(A,B,C)
=\overrightarrow{AB}\times\overrightarrow{AC}
=(x_B-x_A)(y_C-y_A)-(y_B-y_A)(x_C-x_A).
$$

| 叉积符号 | 沿 $A\to B\to C$ 行走 | C 相对有向直线 AB 的位置 |
| :-- | :-- | :-- |
| $>0$ | 左转，逆时针 | 左侧 |
| $<0$ | 右转，顺时针 | 右侧 |
| $=0$ | 三点共线 | 在同一直线上 |

虽然人在 B 点转弯，公式使用的是 $\overrightarrow{AB}$ 与 $\overrightarrow{AC}$，而不是比较两条直线的斜率。竖直边也能用同一公式处理，不需要除法。

<ConvexHullTurnVisualization />

之后反复用到同一条栈维护规则。设栈顶是 B，栈顶的前一个点是 A，准备加入 C：

```text
只要栈内至少有两个点，并且 cross(A, B, C) <= 0：
    弹出 B
    重新取当前栈顶的两个点，再检查 C
最后把 C 压入栈
```

这里必须是 **while**，不是 if。弹出一个点后，新的栈顶仍然可能使边界右转，需要继续弹。

例如 $A(0,0),B(1,2),C(2,1)$ 的叉积为 $1\times1-2\times2=-3$。对于从左向右构造的下边界，B 在连线 AC 的上方，绕过 B 会形成向内凹的折线，因此应该用 AC 替代 A → B → C。

但仅仅“所有转向都合法”并不足以构造凸包：**排序保证我们按正确次序扫描，弹栈负责维护边界的凸性，两者缺一不可。**

### Graham 扫描：先按极角排成一圈

#### 找到一个一定在凸包上的基点

选择 $y$ 最小的点 O；若有多个，取其中 $x$ 最小的点。它是最下面一排点中最靠左的端点，一定是凸包顶点。

以 O 为中心，把其他点按极角从小到大排序。这样就像一根射线从向右方向开始逆时针旋转，按扫到的顺序处理点。**这一步排的是方向，不是横坐标，也不是距离。**

同一射线上的点按离 O 从近到远排序。后面的扫描在共线时弹出近点，因此最终只保留最远的端点。

由于 O 的选法，其他点都在 O 的上方或正右方，不会跨过极角的整圈分界。两个点 P、Q 的极角先后可直接用 $\operatorname{cross}(O,P,Q)$ 的正负判断；一般情况下的任意向量极角排序，则还需要先区分半平面。

#### 按排序后的顺序扫描

从 O 开始，用一个栈维护当前边界。每加入一个点 C，就按前面的规则反复检查、弹栈，最后将 C 入栈。扫描完成后，按栈内顺序连接所有点，再从末尾连回 O。

下面普通案例的排序结果是

$$
O=A,\qquad A\to H\to E\to C\to D\to F\to B\to G.
$$

可以重点观察三个时刻：

| 新加入的点 | 此时要处理的问题 | 栈的变化 |
| :-- | :-- | :-- |
| E | A、H、E 在同一射线上，H 更近 | A → H 变为 A → E |
| D | E → C → D 右转，C 已落在内部 | A → E → C 变为 A → E → D |
| G | F → B → G 右转，B 不再撑住外层 | A → E → F → B 变为 A → E → F → G |

#### 为什么弹出的点可以不要？

按极角扫描时，栈保存已扫描点的凸包边界，从基点出发，不含最后闭合回基点的那条边。新点的极角更大，只可能改变靠近栈顶的末尾部分。

如果 A → B → C 右转，旧路径 A → B → C 不再是外层凸边界；弹出 B 后用 A → C 连接，去掉向内凹的部分。若共线，B 也不是需要保留的拐角。反复弹栈直到恢复左转，即维护了新的凸边界。极角顺序保证不必回头改动栈底附近已经确认的部分。

排序花费 $O(n\log n)$；扫描中每个点最多入栈、出栈各一次，所以扫描本身是 $O(n)$，总复杂度为 **$O(n\log n)$**，额外空间 $O(n)$。

### 上下凸包：Andrew 单调链

Graham 要围绕基点排序；Andrew 则把外边界拆成两条从左端点连到右端点的链，只用最普通的坐标排序。通常更便于实现，也更适合继续学习动态凸包。

#### 先统一排序与走向

把点按 **x 递增、x 相同按 y 递增** 排序并去重。字典序最小的点记为 L，最大的记为 R。

- **下凸壳**：按排序结果正向扫描，从 L 走到 R。
- **上凸壳**：按排序结果反向扫描，从 R 走回 L。

这样两条链的行走方向都与完整凸包的逆时针方向一致，因此它们都使用 `cross <= 0` 时弹栈的同一规则。

> 如果把上凸壳也从 L 扫到 R，转向判定就要反过来。这里选择“正向下壳 + 反向上壳”，是为了让两遍代码完全一致。不要只背一个叉积符号而忽略扫描方向。

#### 下凸壳怎样形成？

仍看普通案例，坐标排序为

$$
A\to G\to B\to H\to C\to D\to E\to F.
$$

一开始 A、G 入栈，轮到 B 时，A → G → B 右转，于是 G 从**下凸壳的候选栈**中弹出。G 虽然是最终凸包顶点，但它属于上边界，这次弹栈并不意味着把 G 从整个输入点集中删除。

轮到 E 时，还可能连续弹出多个点：不能只处理最后一个凹陷。下凸壳最终为 A → E → F。随后反向扫描，上凸壳得到 F → G → A。

#### 两条链如何拼接？

两条链都含有 L、R，所以不能直接把完整数组拼起来。最简单的写法是：**下凸壳去掉末尾的 R，上凸壳去掉末尾的 L，再连接**。

```text
下凸壳：A → E → F     去掉末尾 F，剩下 A → E
上凸壳：F → G → A     去掉末尾 A，剩下 F → G
拼接后：A → E → F → G
```

最后 G → A 这条闭合边由使用凸包的代码按需补上，不重复存储首点 A。

#### 正确性与复杂度

维护下凸壳时，栈中相邻边始终严格左转，已经扫描的点都位于有向链的左侧或边界上。新点按字典序到来，只需要修正链的末尾；右转意味着原栈顶高于新的下边界，弹出它不会漏掉真正的下凸壳顶点。

反向构造上凸壳同理。两条边界围住全部点，并且每个保留点都是边界上的拐角，合并后就是凸包。

两次扫描都是 $O(n)$，排序为 $O(n\log n)$，总时间 **$O(n\log n)$**，额外空间 $O(n)$。代码里出现 `for` 套 `while`，并不意味着 $O(n^2)$：每个点在每一遍扫描中最多被弹出一次。

### C++ 实现：两种方法共用叉积与去重

下面三段代码可放在同一个源文件中。函数接收点集并返回凸包顶点，不依赖具体题目的输入输出格式；坐标为整数，绝对值不超过 $10^9$。使用 GCC/Clang 支持的 `__int128_t` 计算叉积与距离平方，先转为宽整数再相减、相乘，避免中间结果溢出。

```cpp maxLines=10
#include <algorithm>
#include <vector>
using namespace std;
using i128 = __int128_t;

struct Point {
    long long x, y;
    bool operator<(const Point& b) const {
        return x != b.x ? x < b.x : y < b.y;
    }
    bool operator==(const Point& b) const {
        return x == b.x && y == b.y;
    }
};

i128 cross(Point a, Point b, Point c) {
    return (i128(b.x) - a.x) * (i128(c.y) - a.y)
         - (i128(b.y) - a.y) * (i128(c.x) - a.x);
}

i128 dist2(Point a, Point b) {
    i128 dx = i128(a.x) - b.x, dy = i128(a.y) - b.y;
    return dx * dx + dy * dy;
}

void deduplicate(vector<Point>& p) {
    sort(p.begin(), p.end());
    p.erase(unique(p.begin(), p.end()), p.end());
}
```

两个不同的点，或者更多点但全部共线时，两条单调链都只剩两个端点，去重拼接后也恰好返回两个点。

### 共线、重复点与精度：先约定，再写代码

| 情形 | 本文的处理 | 为什么 |
| :-- | :-- | :-- |
| 完全重合的输入点 | 排序后去重 | 同一坐标不应多次成为顶点，也避免零向量 |
| 三点共线 | `cross <= 0` 时弹栈 | 不保留边上的中间点 |
| 空集、单点、两点 | 返回对应退化结果 | 不能访问不存在的栈顶，也不强行闭合成多边形 |
| 全共线 | 返回两个端点 | 不应把整条线来回输出两遍 |
| 坐标较大 | 叉积使用足够宽的整数 | 乘法溢出会直接颠倒转向判定 |

如果题目要求**保留所有边界输入点**，需要改算法的边界约定，而不是仅改变输出格式：

- 对 Andrew，非退化点集可改为只在 `cross < 0` 时弹栈；但全共线必须单独处理，直接返回去重后的排序结果，否则中间点会在两条链中重复。
- 对 Graham，仅把 `<=` 改成 `<` 还不够：最后一条同极角射线上的点，需要按距离从远到近扫描，才能沿闭合边正确保留全部边界点。
- 浮点坐标要根据数值尺度处理近共线情况；`eps` 不是万能精确判定，尤其不要随意把带容差的“不等于”写进排序比较器，破坏严格弱序。

### 小众算法：了解不同的构造思路

#### 卷包裹法（Jarvis march）：每次确定下一条外边界

从一个极点出发，枚举所有点，找出下一顶点 Q，使其他点全部位于有向边 PQ 的左侧或线上；共线时选择离 P 最远的点。反复前进，直到回到起点。

若凸包有 $h$ 个顶点，每走一步扫描 $n$ 个点，总复杂度为 $O(nh)$。当凸包顶点很少时很直接；最坏 $h=n$，会达到 $O(n^2)$。

#### 普通分治与 Chan 算法不是同一个复杂度

普通分治法按横坐标分成左右两半，分别求凸包，再用上下公切线合并，可以做到 $O(n\log n)$。

“先把点分成很多小组求凸包，再对小凸包做卷包裹”的方法则是 **Chan 算法**。猜测顶点数上界为 $k$：

1. 每组最多 $k$ 个点，分别用 Graham 或 Andrew 求凸包，总计 $O(n\log k)$。
2. 在这些小凸包上卷包裹，每个小凸包通过二分找切点，一步 $O((n/k)\log k)$。
3. 最多走 $k$ 步；若还没有闭合，说明猜小了，增大 $k$ 后重新尝试。

不能固定猜 $k=\log n$，也不能直接按 $2,4,8,\ldots$ 普通倍增后就宣称总计只有一个对数。使用 $k=\min(n,2^{2^t})$，即 $4,16,256,\ldots$ 这样的平方增长，各轮代价构成几何级数，最终达到输出敏感的 $O(n\log h)$（退化情况可写作 $O(n\log(h+1))$）。这不是对输入分布作“随机时较快”的假设。[Chan 原论文](https://www.cs.swarthmore.edu/~adanner/cs97/s08/pdf/Chan-OutputSensitive.pdf)

#### QuickHull：找到最远点，把问题拆成两边

先取字典序最小、最大的两个极点 A、B，以**直线 AB** 把其余点分到两侧。AB 一般只是初始分割线，**不一定已经是凸包的一条边**。

只看位于有向直线 AB 左侧的候选点集 S：

1. 若 S 为空，A 到 B 之间没有新的外层点，AB 就是这一侧的一段边界。
2. 否则选离直线 AB 最远的点 C，也就是使 $\operatorname{cross}(A,B,C)$ 最大的点；距离相同时，取最远平行支撑线上的端点，避免选中共线中间点。
3. 分别保留 AC 左侧、CB 左侧的候选点，递归处理 A → C 和 C → B。
4. 三角形 ABC 内部的点，以及不需要保留的共线中间点，不可能再成为这一侧的新顶点，可以丢弃。

另一侧通过交换 A、B，同样处理左侧点。这里形成的 A → C → B 链沿上侧前进，拼出的环可能是顺时针的；若后续算法要求逆时针，应统一调整输出方向。

![几何示意图 3dtubao4](/images/courseware/geometry/3dtubao4.jpg "width=480")

它和快速排序一样有“选一个点，再划分”的形式，但不能因此保证最坏 $O(n\log n)$；二维基本 QuickHull 最坏可达 $O(n^2)$。算法界可对照 [CGAL 的二维凸包说明](https://doc.cgal.org/latest/Convex_hull_2/index.html)。

常规竞赛求静态二维凸包，优先掌握 Graham 或 Andrew。两者的核心不是“套一个叉积公式”，而是**排序确定顺序，栈维护凸性，明确共线点的保留约定**。

### 最小乘积问题

QuickHull广泛应用于这样一类问题：

一个问题的每个解的元素都有两个属性x,y，现在要找到一组最优解使得$(\sum x)*(\sum y)$最小。

这类两个属性的问题往往不方便解决，但是可以快速解决一个属性的问题。

那么我们令初始的凸包上的两个点为$\sum x$最小的和$\sum y$最小的点。

找到凸包上离直线AB最远的点C就是要使得$\overrightarrow{AB} \times \overrightarrow{AC}$最大。

$w=(x_B-x_A)*(y_C-y_A)-(x_C-x_A)*(y_B-y_A)$，我们把这个式子用乘法分配律展开之后，把所有的x、y都乘上对应的系数就变成了一维的问题了。

##### P5540 [BalkanOI 2011] timeismoney

题目描述：给定连通无向图，每条边有 $a_i$ 和 $b_i$ 两个属性。请求出一个生成树，使得 $\left( \sum_{e \in T} a_i \right) \left( \sum_{e \in T} b_e \right)$ 最小。

$1 \leq n \leq 200$，$0 \leq a_i, b_i < 256$。

<CollapsibleComponent title="做法：凸包解决最小乘积问题">

记 $A = \sum_{e \in T} a_e$，$B = \sum_{e \in T} b_e$，把所有生成树的 $(A, B)$ 给画在二维平面上。

显然 $AB$ 最小的点只能在凸包上出现。先不管复杂度问题，如何把凸包求出来：已知凸包上一段的两个端点，我们可以求出凸包和端点连线的切线，进而找到新的点、递归下去。

洛谷的第一篇题解证明了，横纵坐标都在 $[0, V]$ 中的凸包（凸包要没边有点共线），点数最多为 $V^{2/3}$，因此复杂度可以做到 $O(m V^{2/3} \log m)$。

这种题通过凸壳上二分，把乘积变为了线性。

</CollapsibleComponent>

## Minkowski和

### Minkowski和

给定两个点集P,Q，定义他们的Minkowski和

$P+Q \ = \ \{x1+x2,y1+y2 \ | \ (x1,y1) \in P,(x2,y2) \in Q\}$

给定点集P,Q,求他们Minkowski和的凸包面积

$|P|,|Q| \le 10^5$

根据定义不难发现，在$P+Q$凸包上的点一定由P的凸包上某个点与Q的凸包上某个点相加而得到。

那么问题变成了求两个凸包的Minkowski和。

分析一下P+Q凸包每条边的构成

假设已知凸包的顶点$P_a+Q_b$，那么这个顶点连出去的下一条边只有两种选择：$P_{a+1}+Q_b \ or \ P_a+Q_{b+1}$

##### P8101 [USACO22JAN] Multiple Choice Test P

##### CF1019E Raining season

给一棵树，每条边的边权是一个一次函数$ax+b$

求当$x=0,1,\ldots,m-1$时，树的直径是多少

$n \le 10^5, m \le 10^6$，时间限制$3S$

<CollapsibleComponent title="做法">

对于一条路径，设两种权值的和为$\sum a, \sum b$

显然，可能成为答案的点会在所有$(\sum a, \sum b)$这些点形成的凸包上

考虑边分治，求出两侧的向下路径组成的凸壳，然后跑闵可夫斯基和合并即可。

最后把这$O(n\log n)$个凸壳上的点再重新跑一次凸包

总复杂度$O(n \log^2 n + m)$

</CollapsibleComponent>
