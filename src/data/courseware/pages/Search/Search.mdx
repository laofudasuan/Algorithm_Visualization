# 搜索算法

## 算法介绍

在我们遇到的一些问题当中，有些问题不能够确切的建立数学模型，或即便有数学模型但该模型的准确方法也不一定能运用现成算法

在要求枚举方案时，常常会遇到这一类问题

解决这一类问题，我们一般采用搜索的方法解决，即从初始状态出发，运用题目所给出的条件和规则扩展所有可能情况，从中找出满足题意要求的解答
    
    \begin{frame}{搜索问题框架}
    
    一个\textcolor{red}{搜索问题} 包含:
    
    \begin{itemize}
      \item $S:$ 状态空间
      \item $S_{start}:$ 初始态
      \item Action$(s):$ 可行动作
      \item Succ$(s,a):$ 后继
      \item Cost$(s,a):$ 动作费用
      \item IsEnd$(s):$ 目标函数
    \end{itemize}
    
    一个 \textcolor{red}{解} 是一个从初始态出发到达一个终止态的可行动作序列
    
    \end{frame}
    
    \subsection{基本搜索方法}
    
    \begin{frame}{DFS（深度优先搜索）}
    
    \begin{algorithmic}[1]
    \Function{DFS}{$s$}
      \If{IsEnd$(s)$}
        \State \Return True
      \EndIf
      \ForAll{$a \in$ Action$(s)$}
        \If{DFS(Succ$(s,a)$)}
          \State \Return True
        \EndIf
      \EndFor
      \State \Return False
    \EndFunction
    \end{algorithmic}
    
    \end{frame}
    
    \begin{frame}{DFS(深度优先搜索)}{非递归版}
    
    \begin{algorithmic}[1]
    \Function{DFS}{$s$}
      \State St $\gets$ an empty stack
      \State St.push$(s)$
      \While{St is not empty}
        \State $v \gets$ St.pop()
        \If{IsEnd$(v)$}
          \State \Return True
        \EndIf
        \ForAll{$a \in$ Action$(v)$}
          \State St.push(Succ$(v,a)$)
        \EndFor
      \EndWhile
      \State \Return False
    \EndFunction
    \end{algorithmic}
    
    \end{frame}
    
    \begin{frame}{BFS（广度优先搜索）}
    \begin{algorithmic}[1]
    \Function{BFS}{$s$}
      \State Q $\gets$ an empty queue
      \State Q.push$(s)$
      \While{Q is not empty}
        \State $v \gets$ Q.pop()
        \If{IsEnd$(v)$}
          \State \Return True
        \EndIf
        \ForAll{$a \in$ Action$(v)$}
          \State Q.push(Succ$(v,a)$)
        \EndFor
      \EndWhile
      \State \Return False
    \EndFunction
    \end{algorithmic}
    \end{frame}

    \begin{frame}{八数码问题}
        
        由于题目要找到的解是达到目标最少步骤
        
        因此解题的方法为：从初始状态出发，先把移动一步后的布局全部找到，检查是否达到目标布局，如果没有，再从这些移动一步的布局出发，找到移动两步后的所有布局，再判断是否有达到目标的
        
        如此继续，一直达到目标状态为止，输出结果
        
        由于是按移动步数从少到多产生新布局的，所以找到的第一个目标一定是移动步数最少的一个，也就是最优解

    \end{frame}
    
    \begin{frame}{深搜和广搜的对比}

        \begin{itemize}
            \item 深搜每个时候只需要开一个状态，广搜需要开一个队列，存很多个状态
            \item 当状态量为无穷，求最小步数时，只能选择广搜
        \end{itemize}
        
    \end{frame}

    \subsection{$\text{A}^*$ 搜索}
    
    \begin{frame}{$\text{A}^*$}
    \pause
    \begin{itemize}[<+->]
      \item 求状态图上一个点到另一个点的最短路
      \item 令$g(x)$表示从起点出发到达$x$的已走距离
      \item 用一个启发式函数$h(x)=x$表示到达终点的估测距离
      \item 令$f(x)$表示$x$这个方案的估价：$f(x)=g(x)+h(x)$
      \item 步骤：
        \begin{enumerate}
            \item 把起点放入优先队列
            \item 从优先队列中取出$f(x)$最小的元素
            \item 如果$x$为终点，直接结束
            \item 否则枚举$x$的所有出边$(x \to y)$，把$y$放入优先队列中，回到步骤2
            \item 保存路径，从终点开始，沿着父节点移动至起点，即为路径
        \end{enumerate}
    \end{itemize}
    \end{frame}

    \begin{frame}{启发式函数}
    
        \begin{itemize}
            \item 一个启发式函数 $h$ 是 \textcolor{red}{admissible}(Optimistic) 当且仅当 :
        
            $$0 \le h(n) \le h^*(n)$$
        
            其中 $h^*(n)$ 是到达终点的\textbf{真实距离}
        
            \item Consistency:
        
            $$h(A)-h(C) \le w_{a,c}$$
        \end{itemize}
    \end{frame}

    \begin{itemize}
      \item 问题在哪？
      \item 真实距离$<$估测距离
      \item 所以估测距离必须$\le$真实距离
    \end{itemize}
    \end{frame}

    \begin{multicols}{2}

      \item $A$ 是最优解
      \item $B$ 是一个非最优解
      \item $h$ 满足 admissible
    \end{itemize}
    
    结论:
    
    \begin{itemize}
      \item $A$ 将比 $B$先访问到
    \end{itemize}

    \end{multicols}
    
    \end{frame}
    
    \begin{frame}{树上A*搜索最优性}
    
    \begin{multicols}{2}
    
    证明:
    
    \begin{itemize}
      \item $n$为$A$的某一个祖先（可以是$A$自己）
      \item 结论: $n$ 将比 $B$ 先访问
      \item 令$g(n)$为到达$n$已经走过的费用总和
      \item $f(n)=g(n)+h(n)$
      \item $f(n) \le g(A)$: Admissibility
      \item $g(A)=f(A)$
      \item $g(A)<g(B)$
      \item $f(A)<f(B)$
    \end{itemize}

    \begin{frame}{MinMax Search}
    
    \begin{multicols}{2}
    \begin{algorithmic}[1]
      \Function{Max-Value}{state}
        \State $v \gets -\infty$
        \ForAll{each successor of state}
          \State $v \gets \max(v,$Min-Value(succ)$)$
        \EndFor
        \State \Return $v$
      \EndFunction
    \end{algorithmic}
    \begin{algorithmic}[1]
      \Function{Min-Value}{state}
        \State $v \gets \infty$
        \ForAll{each successor of state}
          \State $v \gets \min(v,$Max-Value(succ)$)$
        \EndFor
        \State \Return $v$
      \EndFunction
    \end{algorithmic}
    \end{multicols}
    
    \pause
    
    时间复杂度$O(b^m)$
    
    空间复杂度$O(m)$
    \end{frame}
    
    \begin{frame}{Alpha-Beta 剪枝}
    
    \begin{multicols}{2}
    \begin{algorithmic}[1]
      \Function{Max-Value}{$state,\alpha,\beta$}
        \State $v \gets -\infty$
        \ForAll{each successor of state}
          \State $v \gets \max(v,$Min-Value$(succ,\alpha,\beta))$
          \If{$v \ge \beta$}
            \State \Return $v$
          \EndIf
          \State $\alpha \gets \max(\alpha,v)$
        \EndFor
        \State \Return $v$
      \EndFunction
    \end{algorithmic}
    \begin{algorithmic}[1]
      \Function{Min-Value}{$state,\alpha,\beta$}
        \State $v \gets \infty$
        \ForAll{each successor of state}
          \State $v \gets \min(v,$Max-Value$(succ,\alpha,\beta))$
          \If{$v \le \alpha$}
            \State \Return $v$
          \EndIf
          \State $\beta \gets \min(\beta,v)$
        \EndFor
        \State \Return $v$
      \EndFunction
    \end{algorithmic}
    \end{multicols}

        设$g(x)$为正整数$x$的约数个数

        若对于任意$0<y<x$($y$为整数)，都有$g(x)>g(y)$，就把正整数$x$叫做反质数
        
        给定正整数$m,n$,且$m \le n \le 20000000$，求$[m,n]$内所有的反质数
        
        若没有，输出NO

        时限1s，空限64M

        
    \end{frame}

    \begin{frame}{[Openjudge7591]反质数}
        开始的思路是直接暴力求区间内所有数的质数个数
        
        既然这道题目叫反质数，也许能和质数扯上关系
        
        一个数的因数个数=各个质因数个数+1的乘积

        例如$12=2 \times 2 \times 3$，因数个数就有$(2+1) \times (1+1)=6$个

        验证一下,(1,2,3,4,6,12),的确没错

    \end{frame}

    \begin{frame}{[Openjudge7591]反质数}
        
于是就得到一种搜索的思路：枚举使用哪些质数以及使用它们的个数。越大的质数，性价比是越低的(在增加同等因数个数的情况下，大质数增加的大小会更多)，于是只需要取一定范围内的质数。我们只要判断各种质数组合相乘结果之间的关系就可以了。

可以发现$2 \times 3 \times 5 \times \ldots \times 23$和$2^{25}$都大于$20000000$，于是我们只需枚举$2 \sim 23$内的质数，每个质数选的个数不超过25个

一旦乘积超过$n$就立即返回，这样时间复杂度是完全可以接受的

    \end{frame}

    \begin{frame}{HNOI2013比赛}
    
        一场足球赛共$N$支球队参加，比赛规则如下：
        
        \begin{itemize}
            \item 每两只球队之间踢一场比赛
            \item 平局各得一分
            \item 胜利得三分，败者不得分
        \end{itemize}
        
        给定每个球队的最终得分，求有多少种可能的比赛结果，$N \le 10$
        
    \end{frame}

    \begin{frame}{HNOI2013比赛}
        首先考虑的是直接枚举

        但是状态量太大了
        
        十支队伍，四十五场比赛，复杂度有$3^{45}$
        
        显然会TLE

        然后就只有$40 \sim 70$分了

    \end{frame}

    \begin{frame}{HNOI2013比赛}
        所以我们考虑这样一种搜索方式：

        开始设一个序列，里面存每个队伍的最终分数，然后对这个数组进行操作，最终让所有分数变成0，那么就算是一种方案。

    \end{frame}

    \begin{frame}{HNOI2013比赛}
        假如有4个队伍，两两之间没有比赛过

        序列1:(4,2,3,5)

        序列2:(5,3,2,4)

        可以高兴地发现这两个序列的答案是一样的

        也就是说，顺序不会影响答案        
    \end{frame}

    \begin{frame}{HNOI2013比赛}
        那么可以这样搜：
        
        每次选一个队伍，枚举它与其他所有队伍的胜负情况。如果最终使其得分为0，那么就可以进入下一个队伍。并且这时，我们知道剩下队伍的得分序列，这些队伍两两之间都没有比赛过
    
        既然顺序不影响一个序列的答案，那么重复的状态（即搜完一个队伍后，剩下队伍的得分序列）会非常多

        每次搜完，对剩下队伍的得分序列排序并哈希，看是否已经出现过这个状态。出现过就直接调用答案，否则就把它记为新状态
    \end{frame}

    \begin{frame}{HNOI2013比赛}
        哈希可以用类似字符串哈希的方法做。设一个质数b，然后对剩下的序列不断进行乘和加的操作

        假设b=31，剩下的序列是(3,2,4,5)
        
        那么就用$((3 \times 31+2) \times 31+4) \times 31+5$这个数来代表这个序列
        
        之所以这样做，是因为通过这个数也可以还原序列
        
        拿上面那个数举例，取余31就得到5，然后再自除31，继续取余得到4
        
        以此类推就得到整个状态
    \end{frame}

    \begin{frame}{埃及分数}
        用若干个形如1/n的分数之和表示a/b
        
        加数个数越少越好，加数个数相等的话，最小的加数越大越好
        
        加数中不允许有相同的，求最好的表示形式

        $0<a,b<1000$，保证有解
        
        时限1s，空限128M
    \end{frame}

        除了从小到大枚举加数以外似乎找不到别的办法

    \begin{frame}{埃及分数}
        规定搜索的层数之后，每层都从小到大枚举分母，可以得到两个剪枝

        1.如果剩余每一层都使用当前枚举的分数，最后的和仍然不大于a/b，那么这个分数以及它之后的分数都不用考虑

        2.搜完倒数第二层，最后一层就确定了

    \end{frame}

    \begin{frame}{埃及分数}
        一个例子:$\frac{19}{45}$

        首先深度=1，显然没有解

        然后深度加1变成2

        这是满足条件的，搜索就完成了
    \end{frame}

        \item 搜索的时候去重，第$k$层数字不会超过$\frac{A}{2^k}$
        \item 复杂度$O((n+A_i)\log(n))$
    \end{itemize}
\end{frame}

      \end{itemize}

    \begin{frame}{凤仙花}
      
    考虑确定了每个问号为 $L / R$ 之后，那么一个操作序列可以到达的位置是一个矩形。

    考虑meet in the middle，把操作序列对半划开，枚举前一半和后一半能到达的矩形。进行一些平移反转操作后，可以将问题转化为：判断能否从两个集合里各选选一个矩形，使得这两个矩形有交的问题。直接扫描线维护线段树即可。

    时间复杂度$O(2^{n/2} poly(n))$。
    \end{frame}

    \begin{frame}{凤仙花}
      注意到第奇数步控制 $y$，第偶数步控制 $x$。如果存在两个连续的$?$，目前该移动$y$，那么无论方向选择正或负都不影响下一步的决策。比如我两个$??$ 之后希望向右走，那么我如果第一个问号选了上，第二个就右拐就向右了，否则就左拐还是可以向右。这两种情况下 $x$ 轴的影响都是选择了正方向也就是右侧，但是$y$轴的选取却不同。这提示我们当有连续 $??$ 的时候，第一个$?$ 是几乎不具有后效性的。

      比如最极端的例子——全是 $?$。那么第奇数步和偶数步会的变得完全独立。可以分成两个子问题，每个子问题继续沿用meet in the middle，而且会简化为 区间是否有交，而不是矩形是否有交。

    \end{frame}

    \begin{frame}{凤仙花}
      对于不那么极端的情况。考虑标记所有 $L, R$ 操作以及他们的前一个操作。对于已经标记的 $?$ 操作暴力枚举他们的方向，剩余分裂成两个独立的部分，分别 meet in the middle。

      考虑分析上述做法的时间复杂度，假设 $?$ 个数为 $B$。

      做法1的时间复杂度是 $O(2^{B/2} poly(n))$。
    
      做法2的时间复杂度是 $O(2^{n-B} 2^{(B - (n - B)) / 4} poly(n)) = O(2^{3n/4 - B/2})$。

      取 $B = 3/4n$ 的时候两个复杂度达到平衡，时间复杂度为$O(2^{3n/8} poly(n))$
    \end{frame}

    \begin{frame}{牛顿迭代算法}
    
    \begin{multicols}{2}
    
    \includegraphics[width=5cm]{search/G10.jpg}
    
    $$y=f'(x_n)(x-x_n)+f(x_n)$$
    
    $$0=f'(x_n)(x_{n+1}-x_n)+f(x_n)$$
    
    $$x_{n+1}=x_n-\frac{f(x_n)}{f'(x_n)}$$
    
    \end{multicols}

    \begin{frame}{错误点}
    
    \begin{description}
      \item[错误的初始点] 
      $$f(x)=1-x^2$$
    
      $x_0=0$, $f'(0)=0$.
      \item[循环的初始点] 
      $$f(x)=x^3-2x+2$$
    
      Start from $x_0=0$.
    
      $$x_1=x_0-\frac{f(x_0)}{f'(x_0)}=-\frac{2}{-2}=1$$
    
      $$x_2=x_1-\frac{f(x_1)}{f'(x_1)}=1-\frac{1}{1}=0$$
    \end{description}

    \subsection{图迭代}
    
    \begin{frame}{图迭代}
    
    \begin{block}{赌徒问题}
    
    有一个赌徒，初始有$k$元，每次他有$p$的概率赢一元钱，有$1-p$的概率输一元钱，当他赢到$m$元时就会离开，当手上没有钱时就会破产，问赌徒一直玩下去离开的概率
    
    \end{block}
    
    \pause
    
    迭代做法：
    
    随机一个函数$f_0:[m] \to [0,1]$
    
    $\forall n \in \mathbb{N}^+$, $f_n(x)=pf_n(x-1)+(1-p)f_n(x+1)$
    
    \end{frame}
    
    \begin{frame}{图迭代}
    
    \begin{block}{赌徒问题2}
    
    有一个赌徒，初始有$k$元，每次他可以押注$t$元，然后有$p$的概率再赢$t$元钱，有$1-p$的概率输掉这$t$元，当他赢到$\ge m$元时就会离开，当手上没有钱时就会破产，问赌徒一直玩下去离开的概率
    
    \end{block}
    
    \pause
    
    迭代做法：
    
    随机一个函数$f_0:[m] \to [0,1]$
    
    $\forall n \in \mathbb{N}^+$, $f_n(x)=\max_{y \in [1,x]}pf_n(x-y)+(1-p)f_n(x+y)$
