我中学打信息学竞赛的时候，会因为解决问题的需要，去学习一些大学数学课程，比如线性代数、微积分、概率论。当时我买了几本比较有名的教材，比如同济大学的《高等数学》、高等教育出版社的《概率论与数理统计》。但是，我在看的过程中就感觉非常痛苦，因为这些教材都是采用的非常严谨的数学语言，进行的一步步推导。但是这就使得我在阅读的过程中觉得非常难以理解，我不知道每一步为什么要这么做，只知道这样推确实是对的？

后来到了大学，我发现很多数学老师在课堂上讲课也是如此，课件上密密麻麻的公式、定理、证明，我就像个机器一样一步步跟着算。相比之下，我觉得写代码是一件更有趣的事情，因为我可以从我的一个初始想法，再一步步形成算法框架，再到最后形成最终我自己的程序。而且，更加糟糕的事情是，这些数学老师并不会意识到自己这样讲学生是很难理解的，因为他们已经在学校讲了几十年，所有的教学环节、话术早就已经固化了，他们就认为这是对学生最好的讲课方式。

每当在看书的时候或者在课堂上遇到困惑时，我会上网去搜索我的问题。而在复杂的网络世界中，一位叫做3blue1brown的开发者引起了我的注意。他开发了一个名为manim的数学动画软件，能将各种数学公式、函数、曲线等元素用动画的形式进行呈现。有很多视频博主用manim制作了各种各样的数学内容讲解视频。我发现，画面中这些流动的数学符号，配合上这些博主更说话式的语言讲解，枯燥的数学一下就变得生动有趣了起来。

而这一现象也是可以从脑科学进行解释的，我给大家分享一个我在知乎上看到的总结得很到位的评论：

我面试过不下几百个名校毕业的数学系、计算机系学生。有个非常普遍的现象，简历上写着精通线性代数、微积分、概率论，绩点也高得吓人，但你只要稍微往下深究一点，问问这些数学概念背后的几何直观，或者问问他们在实际工程里到底怎么映射，大部分人就开始支支吾吾，最后只能在白板上给我默写公式。

这真不怪学生，也不全是老师的问题。核心矛盾在于，我们传统的数学教材编写逻辑，和人类大脑理解世界的底层逻辑，这两者之间存在着巨大的断层。3blue1brown（下面简称3b1b）之所以能火，能让这么多人觉得醍醐灌顶，是因为Grant Sanderson做对了一件事，他把数学从反人性的公理化体系里拽了出来，还原成了人类大脑最喜欢的视觉信号。

你要明白，数学课本和数学研究是两码事。数学课本，尤其是国内理工科通用的那些老教材，它们的编写遵循的是布尔巴基学派的风格。这帮法国数学家崇尚绝对的严谨和形式化，他们认为数学应该从公理出发，通过逻辑推导产生定理，再由定理构建大厦。这种结构在逻辑上是完美的，无懈可击，对于已经掌握了数学全貌的人来说，这是最高效的信息索引方式。

但是，对于初学者，这简直就是灾难。

人类的大脑进化了几百万年，我们的视觉皮层极其发达，我们擅长捕捉运动、空间关系、形状变化。我们最不擅长的就是处理抽象的线性符号序列。

你回想一下你的线性代数课本第一章讲的是什么。大概率是行列式的定义，那个充满了逆序数和全排列的公式。非常严谨，非常正确，但没有任何物理意义。学生死记硬背把它算出来了，考了满分，但依然不知道这东西到底代表什么。

3b1b是怎么做的？他完全抛弃了先定义后性质的课本逻辑。在《线性代数的本质》里，他甚至到很后面才提到行列式的计算公式。他花了大篇幅告诉你，矩阵本质上是空间的线性变换。

这里我举个具体的场景，也是我面试经常用的题目。我们做推荐系统或者图像处理，经常要用到特征值分解或者奇异值分解。我问候选人，特征值和特征向量到底是什么？

如果是看课本长大的学生，通常反应是立马写下 Ax=cx，然后告诉我把 A 减去 lambda I 的行列式设为零，解方程。这没错，但这只是计算手段。

看过3b1b或者真正理解数学的人会告诉我，矩阵是空间的拉伸、旋转或剪切。在这个变换过程中，绝大部分向量的方向都变了，被打乱了。但是，空间里存在那么几根特殊的轴，或者说几个特殊的向量，它们在变换前后仅仅是被拉长或缩短了，方向死活没变。这些顽固的向量就是特征向量，拉伸的倍数就是特征值。

这两种回答的含金量在工业界是天壤之别。

后者意味着当你面对一个高维数据降维的问题时，你知道保留特征值大的特征向量，其实就是保留了数据里信息量最大的主要方向，丢弃了噪音。这叫直觉，这叫Insight。前者只能对着代码里的 numpy.linalg.eig 调包，一旦参数不对，根本不知道怎么排查问题。

3b1b 的牛逼之处在于利用 Manim 引擎把数学原本的动态属性还给了它。但是，视频流过得太快，很多时候你以为懂了，其实只是眼睛爽了。如果你想把视频里的直观感受真正固化成大脑里的知识结构，我非常建议你配合这份 3Blue1Brown线性代数笔记：可能是全网最好的中英文整理 一起看。它补充了视频里略过的推导细节，能帮你记住。

微积分在课本里是静态的。极限的定义是用 epsilon-delta 语言写的，那是一套为了堵住逻辑漏洞而发明的法律条文，枯燥且反直觉。但在牛顿和莱布尼茨手里，微积分是流动的，是变化的率。3b1b 的视频里，你能看到 dx 是一个真实的、微小的增量，导数就是函数图像切线斜率随着 x 移动而产生的动态变化。这种连续的、动态的视觉输入，直接击中了我们大脑的视觉处理核心，绕过了那个负责抽象符号处理的低效关卡。

所以学生觉得懂了，因为大脑觉得舒服了，认知负荷降低了。

不过，作为在行业里摸爬滚打这么些年的老兵，我得在这里泼一盆冷水。而且这盆水必须泼。

很多学生在 3b1b 上产生的这种学懂了的感觉，其实包含着巨大的认知错觉。心理学上管这个叫能力错觉。你看视频的时候，顺着他的动画逻辑走，每一步都顺理成章，你觉得哇塞太简单了，原来如此。但这就像你看顶级大厨做菜，刀工行云流水，你看着觉得切土豆丝也就那样，有手就行。等你真进了厨房，拿起刀，你会发现你连土豆皮都削不明白。我在团队里见过不少眼高手低的新人，聊起概念头头是道，什么傅里叶变换是频域时域转换，什么梯度下降是下山找路，说得都很溜。因为这些直观解释在网上、在 3b1b 里到处都是。

但是，一旦实际业务中遇到 Loss function 不收敛，需要他手推一下反向传播的梯度，或者需要针对特定的业务场景修改一下正则化项，这些人立马歇菜。因为他们脑子里只有那张动画图，没有符号推导的肌肉记忆。

数学终究是一门形式语言。直观图景是入门的钥匙，能让你不害怕，能让你建立宏观的物理图像。但符号推导是行走的双腿。

关于线性代数，除了 3b1b，我强烈推荐 Linear Algebra Done Right。它推迟行列式的引入，通篇讲算子和空间，读起来像小说。如果你想系统性地把地基打牢，不想被国内教材的枯燥劝退，可以看看这份 76本国外经典教材，全方位覆盖代数、几何、分析、概率等核心领域。课本虽然枯燥，但那些推导过程是必不可少的思维体操。

3b1b 帮你跳过了把直觉翻译成符号的最痛苦的过程，直接喂给你结果。但如果你想成为真正的专家，这一步是省不掉的。你必须在有了直观理解后，强迫自己回到课本，看着那些枯燥的公式，脑子里能自动播放出 3b1b 的动画。能做到这一点，才叫真懂。

真正的学习路径应该是这样的：先看视频建立直觉，再看硬核教材推导公式，最后写代码实现验证。特别是写代码这一步，对于我们搞计算机、搞算法的人来说至关重要。你觉得你理解了矩阵乘法，那你能不能不用 numpy，自己写两个 for 循环或者优化一下并行计算来实现它？你觉得你理解了梯度下降，能不能手写一个线性回归的优化器？

当你试图把数学公式转换成代码的时候，你会发现很多细节是你光看视频、光看书根本注意不到的。数值稳定性、计算复杂度、边界条件，这些才是工程落地的深坑。

我这十几年沉淀下来，发现有那么几类资源和方法，是真正能把数学学通透的。我也别藏着掖着，直接分享出来，希望能给想在这个行业深耕的年轻人一点帮助。这些资源比国内大部分照本宣科的教材要强很多。

关于线性代数，除了 3b1b，我强烈推荐 Sheldon Axler 写的 Linear Algebra Done Right。这本书有个非常有意思的中文译名，好像叫线性代数应该这样学。这本书极其激进，作者认为行列式在教学初期是个绊脚石，掩盖了线性算子的本质，所以他在前几章完全推迟了行列式的引入。他通篇都在讲算子、空间、投影、基底。读这本书，你会感觉像是在读小说，逻辑非常顺畅。它能帮你把脑子里的那些死公式全部清洗一遍，建立起真正的线性空间观。配合 3b1b 看，效果炸裂。

如果你是搞深度学习的，或者准备往 AI 方向转，不要去死磕数学系的《矩阵论》，那里面很多技巧你一辈子都用不上。你应该去看专门为 ML 设计的材料，比如 Matrix Calculus for Deep Learning。这就很务实，只讲对神经网络有用的矩阵求导，布局简洁，针对性极强。我们做算法的，学数学要讲究 ROI，投入产出比。

微积分方面，如果你觉得同济那本实在看不下去，可以找找普林斯顿微积分读本，或者更硬核一点，去啃一下 Spivak 的 Calculus。当然，对于大部分工科生，Gilbert Strang 老爷子的公开课是必看的。不管是线性代数还是微积分，老爷子讲课那种风度，那种把数学当做工具来解决问题的工程美感，是很多纯数学背景的老师不具备的。他会反复强调四个基本子空间，强调投影矩阵，这些都是信号处理和数据压缩的基石。

还有一个被很多人忽略的神书，叫 Visual Complex Analysis，复分析可视化。复变函数在很多工科教材里就是一堆莫名其妙的积分公式和留数定理，学完了一头雾水。这本书简直是数学界的艺术品，全是图。它用几何方法解释了欧拉公式为什么是那个样子，解释了复积分的几何含义。读这本书有点门槛，但如果你能静下心来读进去，你会跪着看完。

除了书，我再强调一遍，一定要动手。

现在很多学生眼高手低，看懂了就以为会了。你试着去 Kaggle 上找个最简单的数据集，不要调包，完全用基础的数学公式去手写一个逻辑回归，手写一个 PCA。在这个过程中，你会遇到各种矩阵维度对不上的问题，会遇到梯度爆炸的问题。解决这些问题的过程，才是你真正把数学内化为自己能力的过程。

在这个行业里混，最后拼的不是谁背的 API 多，也不是谁看过的科普视频多。拼的是面对一个全新的、复杂的、没见过的业务问题时，你能不能把它抽象成数学模型，能不能看出变量之间的内在关系。这种能力，3b1b 给不了你，课本也给不了你，只能靠你自己把这两者结合起来，在无数次的推导和代码实现中磨练出来。

所以，别光顾着在知乎上收藏这种回答，也别光顾着在 B 站上刷视频爽。爽完了，记得把书翻开，把草稿纸铺开，把 IDE 打开。那才是正事。

数学是很公平的。你糊弄它，它在工程上绝对会糊弄你。你看那些顶级的算法大佬，写 Paper 的时候，推导过程行云流水，不是因为他们天生聪明，是因为他们在你看不见的地方，把那些枯燥的定义和定理，反反复复咀嚼了无数遍，直到这些符号在他们脑子里变成了鲜活的图像。

希望大家都能迈过那个从看懂到真懂的坎。路挺长的，但走通了，风景独好。
